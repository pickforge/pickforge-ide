# Sparkle Updates

Pickforge must not enable Sparkle until the macOS release artifact is signed,
notarized, downloadable over HTTPS, and backed by rollback-ready appcast
metadata.

## Required Release Inputs

- Signed and notarized `.app` packaged as a `.zip` or `.dmg`.
- HTTPS appcast URL for `SUFeedURL`.
- EdDSA public key in the app `Info.plist` as `SUPublicEDKey`.
- EdDSA signature and byte length generated by Sparkle's `sign_update` tool for
  the downloadable archive.
- Release notes URL for each appcast item.
- Rollback decision for the previous stable archive and appcast entry before
  publishing the new item.

## Appcast Contract

Pickforge appcast items must include:

- `<sparkle:version>` with the internal build number.
- `<sparkle:shortVersionString>` with the user-facing version.
- `<sparkle:releaseNotesLink>` pointing at HTTPS release notes.
- `<enclosure>` with an HTTPS `url`, `type="application/octet-stream"`,
  positive `length`, and `sparkle:edSignature`.

The example appcast lives at `docs/distribution/sparkle-appcast.example.xml`.
Validate it, or a release appcast, with:

```bash
scripts/macos_sparkle_appcast_smoke.sh
scripts/macos_sparkle_appcast_smoke.sh --appcast path/to/appcast.xml
```

This smoke verifies metadata shape only. The final P7.T3 Sparkle checkbox still
requires a native macOS run with a signed/notarized app, real Sparkle EdDSA
keys, real archive signatures, and a visible update/rollback pass.

## Enablement Gate

Only enable runtime Sparkle after all of these are true:

- Apple Developer ID signing and notarization pass on a native macOS host.
- Gatekeeper launches the downloaded artifact.
- The appcast smoke passes for the production appcast.
- `sign_update` output for the archive is copied into the matching appcast item.
- Release notes are published before the appcast is published.
- Rollback is tested by restoring the prior appcast item and archive.
